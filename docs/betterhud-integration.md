# BetterHud: исследование клиентского HUD

Изучена локальная версия BetterHud 1.14.1 в соседней папке `BetterHud`.
Изменения в BetterHud не вносились.

## Как формируется интерфейс

1. `hud/HudImpl.kt` загружает HUD и его `layouts`. Для каждого layout создаётся
   `HudParser`, включая варианты кадров анимации. Позиция состоит из процентной
   привязки `GuiLocation` и смещения `PixelLocation`.
2. `HudParser` объединяет `HudImageParser`, `HudTextParser`, `HudHeadParser`.
   Условия и плейсхолдеры вычисляются на сервере.
3. Картинки становятся символами bitmap-шрифта. Текст использует отдельные
   сгенерированные шрифты, включая фон, emoji и разбиение на строки.
   Имена шрифтов могут быть закодированы через `EncodeManager`.
4. `LayoutComponentContainer` добавляет положительные/отрицательные пробельные
   символы, размещает элементы по X и возвращает курсор после каждого элемента.
   Поэтому ширина всей строки не описывает видимые границы HUD.
5. `HudPlayerImpl.update()` объединяет компоненты HUD, всплывающих элементов
   и дополнительных компонентов. Результат отправляется как имя bossbar через NMS.
6. `util/Huds.kt:createAscent` кодирует ID шейдера и вертикальную координату
   в отрицательный ascent bitmap-шрифта. В этой версии `HEIGHT_BIT=13`,
   `MAX_BIT=10`, `ADD_OFFSET=4095`.
7. `ShaderManagerImpl.compileShader()` создаёт switch по ID. `text.vsh`
   декодирует высоту, убирает смещение центра bossbar, применяет масштаб
   относительно pivot, добавляет процентные GUI-привязки, слой и эффекты.
   Текст и картинки остаются обычными глифами с точки зрения протокола Minecraft.

## Клиентский редактор

При перезагрузке ресурсов читается действующий `minecraft:shaders/core/rendertype_text.vsh`,
включая overlay выбранной версии. Поддерживаются выражения генератора выше:
процентные привязки, масштаб по каждой оси, pivot, статический масштаб через
`uiScreen`, слои, прозрачность и свойства. Неизвестные выражения внутри преобразований
отключают редактор для этого шейдера. Исходный шейдер не изменяется.

При отрисовке имени bossbar читаются реальные метрики шрифтов Minecraft.
По закодированным Y и таблице шейдера восстанавливаются экранные прямоугольники.
Визуально соседние глифы объединяются в группы. Изменяется только локальная
отрисовка: последовательности глифов получают смещение, компенсированное на
масштаб соответствующего шейдера. Содержимое пакетов, шрифты и плейсхолдеры
сервера остаются исходными.

## Границы точности

- Исходные имена HUD/layout и их семантическое разделение не передаются клиенту.
  Пространственная группа не обязательно совпадает с YAML-layout.
- Плотно расположенные блоки могут объединяться; большие промежутки внутри
  одного layout могут разделять его на группы. Прозрачные поля bitmap-глифов
  также влияют на определение границ.
- Шейдерные волны и другие эффекты могут немного выходить за статическую рамку.
- Изменение видимости частей HUD, шрифтов, геометрии и порядка одинаковых групп
  может изменить их сопоставление с сохранёнными позициями.
- Изменённая программа шейдера получает отдельный профиль. Изменения только
  в содержимом шрифтов при прежнем шейдере не создают отдельный профиль.
- Редактор не меняет полосу bossbar, обычные меню, ванильный HUD или чат.

Точная проверка группировки требует фактического ресурспака и отображаемого
HUD сервера. Обычный запуск клиента подтверждает загрузку модуля и mixin,
но не подтверждает визуальную корректность конкретного серверного интерфейса.
